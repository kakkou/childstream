# ChildStream 安全性強化 設計書

作成日: 2026-09-22
状態: 実装済み・Windows実機確認待ち
対象ブランチ: codex/childstream-safety-hardening
基準コミット: d41693eb27691516e96df42a05396f1dfe3bd17c

## 1. 目的

ChildStreamが自身の作成したWindows Child Sessionだけを識別・操作し、検証済みのSunshineをネットワーク公開範囲を限定して導入できるようにする。また、セットアップ前のシステム状態を正確に復元可能にする。

次の状態を完了条件とする。

- 通常のRDPセッションをChildStreamのChild Sessionと誤認しない。
- 「End session」は、WTSの正式APIが返したChild Sessionだけをログオフできる。
- Sunshineを変更されない固定URLからダウンロードし、展開前にSHA-256を検証する。
- セットアップによる変更を実施前に記録し、ロールバックできる。
- display.cfgが不正な場合は、既定値へ黙ってフォールバックせず接続を中止する。
- Windows向けCIで、コンパイル・設定解析・PowerShell処理の退行を検出する。
- .NET Framework 4.xと簡潔なランチャー構成を維持する。

## 2. 対象範囲

### 対象に含めるもの

- Child Sessionの正確な検出とログオフ。
- コンソール側ランチャーからChild Session側起動スクリプトへの、短時間だけ有効な起動許可情報の受け渡し。
- 条件不一致時に何も起動しないSunshine自動起動。
- タスクスケジューラを利用した、可能な限りUACを表示しない最高権限起動。
- SunshineのバージョンとSHA-256固定。
- FirewallルールのPrivateプロファイル・LocalSubnet限定。
- セットアップ前状態の保存とuninstall／rollbackスクリプト。
- display.cfgの厳格な検証。
- Windows CIと自動テスト。
- インストール、復元、実機確認手順の文書化。

### 対象に含めないもの

- Windowsサービスや常駐する特権ブローカーの追加。
- 複数Child Sessionへの対応。
- DPAPIによる資格情報保存方式の置き換え。
- HDR、ディスプレイドライバー、音声、コントローラー、エンコーダーの変更。
- 上流リポジトリへのPull Requestの自動作成。
- ユーザーが作成したSunshineの資格情報や設定を、回復不能な形で削除する処理。

## 3. セキュリティモデル

Child Sessionを識別する権限主体は、コンソール側で動作するChildStream.exeとする。ChildStream.exeは親セッションからWTSGetChildSessionIdを呼び出し、その結果を短時間だけ有効な起動許可情報として発行する。

Child Session側のスクリプトは、「物理コンソールではない」という条件からChild Sessionであると推測してはならない。すべての検証条件が一致した場合だけSunshineを起動する。状態が存在しない、古い、壊れている、または矛盾している場合は起動せず、診断ログだけを残す。

セッション終了では、セッション列挙やユーザー名の部分一致を使用しない。qwinstaの出力解析とlogoff.exeの呼び出しを廃止する。

## 4. コンポーネント

### 4.1 ランチャーのセッションAPI

ランチャーはwtsapi32.dllの次の正式APIをラップする。

- WTSEnableChildSessions
- WTSIsChildSessionsEnabled
- WTSGetChildSessionId
- WTSLogoffSession

Child Session IDを有効と判断する条件は次のすべてとする。

- WTSGetChildSessionIdが成功する。
- 戻り値がUInt32.MaxValueではない。
- 戻り値がランチャー自身のSession IDではない。

トレイメニューの「End session」は、操作直前にChild Session IDを再取得し、そのIDだけをWTSLogoffSessionへ渡す。検出またはログオフに失敗した場合はエラーを表示し、セッション列挙へフォールバックしない。

### 4.2 起動許可状態

RDP ActiveXが接続状態になった後、ランチャーは有効なChild Session IDを一定時間ポーリングし、次のファイルへ原子的に書き込む。

    %LOCALAPPDATA%\ChildStream\active-child-session.json

状態には次を記録する。

- スキーマバージョン
- Child Session ID
- ランチャーのプロセスID
- ランチャープロセスのUTC起動時刻
- UTC発行時刻

一時ファイルへ書き込んだ後、置換または移動することで、読み取り途中の状態を公開しない。パスワードや秘密トークンは保存しない。

ランチャーは正常な切断、Child Session終了要求、アプリケーション終了時に状態ファイルを削除する。クラッシュ時には残る可能性があるため、読み取り側でも有効期限とランチャーの同一性を検証する。

### 4.3 Child Session側のSunshine起動

起動スクリプトは、1秒間隔で最大60秒間、起動許可状態を待つ。次のすべてが成立した場合だけSunshineを起動する。

- スクリプト自身のSession IDが、発行されたChild Session IDと一致する。
- 起動許可の発行から120秒以内である。
- 発行元ランチャーのプロセスIDが存在する。
- 実際のプロセス起動時刻が、発行された起動時刻と一致する。
- 設定されたSunshine実行ファイルが存在する。
- 同じSession IDかつChildStream同梱版の完全パスでSunshineがまだ実行されていない。

通常利用の別インストール版Sunshineが同じSession IDに存在しても、ChildStream同梱版とはみなさない。同じSession IDの`sunshine.exe`について実行ファイルパスを取得できない場合は、安全側でChildStream同梱版を起動せず診断ログを残す。

検証に失敗した場合は、すべて起動しない側へ倒す。通常の非Childログオンでは、エラーダイアログを表示せず簡潔な診断ログを残す。

### 4.4 最高権限での自動起動

既定のセットアップでは、次の条件を持つユーザー単位のログオントリガー付きScheduled Taskを登録する。

- 現在のWindowsユーザー
- 対話型トークンによるログオン
- 利用可能な最高権限
- ChildStreamのSunshine起動スクリプトを実行するアクション

これにより、Child SessionへのログオンごとにUACを表示せず、管理者権限で動くゲームにも入力を届けられる状態を目指す。

同一ユーザーが複数セッションへ同時ログオンした場合のタスク配置は、Windows 11 Pro実機で確認する必要がある。誤ったセッションでアクションが動作しても、起動許可の照合によりSunshineは起動しない。

実機で最高権限タスクがChild Session内に配置されない場合に備え、厳格なセッション照合を維持したままRunAsで起動するフォールバックモードを用意する。このモードではChild Session内で1回のUAC操作を許容する。今回の改修ではWindowsサービスや常駐特権ブローカーを追加しない。

## 5. display.cfg

display.cfgが存在しない場合は、1920x1080、明示的なスケール指定なしで起動する。

ファイルが存在する場合は、前後の空白を除いたファイル全体が次のいずれかに一致しなければならない。

- WIDTHxHEIGHT
- WIDTHxHEIGHTxSCALE

区切り文字の大文字・小文字は区別しない。値は10進整数とし、次の範囲を含む。

- 幅: 640～8192
- 高さ: 480～8192
- スケール: 指定時は100～500

余分なフィールド、欠落、符号、小数、末尾の余分な文字、整数オーバーフロー、範囲外の値はエラーとする。許容形式を示すメッセージを表示し、パスワード入力やRDP接続を行う前に終了する。

設定解析処理はUIから分離し、RDPを起動せず単体テストできるようにする。

## 6. Sunshineのサプライチェーン対策

セットアップでは次の配布物を固定する。

- バージョン: v2026.914.233613
- ファイル名: Sunshine-Windows-AMD64-lite.zip
- URL: https://github.com/LizardByte/Sunshine/releases/download/v2026.914.233613/Sunshine-Windows-AMD64-lite.zip
- SHA-256: 233008e46f4c0e501a586cbfd6c4fd4a4c0d414a0b5fc7f13c070eb92ec3824b

アーカイブはステージング領域へダウンロードする。展開前にGet-FileHash -Algorithm SHA256で照合しなければならない。不一致の場合はステージング済みアーカイブを削除し、既存のSunshineへ変更を加えず終了する。

ChildStreamが作成した一致するバージョン情報を持たないSunshineディレクトリが存在する場合、既定では上書きしない。明示的に置換を指定した場合だけ、既存ディレクトリを回復可能な場所へ退避してから置換する。既存設定は置換前に保存する。

## 7. Firewallポリシー

ChildStream Sunshine用ルールを次の条件へ限定する。

- 受信方向
- 許可
- Sunshine実行ファイルのパス
- Privateプロファイル
- 接続元RemoteAddressはLocalSubnet

同名の既存ルールがある場合は、変更前にルール本体・アプリケーションフィルター・アドレスフィルターを保存する。アンインストール時には推測した既定値ではなく、保存したルールを復元する。

## 8. トランザクション型セットアップとロールバック

### 8.1 永続状態

最初のシステム変更より前に、次のファイルを作成する。

    %ProgramData%\ChildStream\install-state.json

次の情報を保存する。

- スキーマバージョンとインストール元ディレクトリ
- Child Sessionsの変更前の有効状態
- 変更する各レジストリ値の存在有無・型・値
- 既存Firewallルールと関連フィルター
- 既存スタートアップフックの内容
- 既存Scheduled TaskのXML
- 既存デスクトップショートカットのバックアップ
- 既存Sunshineの状態とバックアップ先
- ChildStreamが新規作成した成果物

資格情報は保存しない。

最初に作成した正常な変更前スナップショットは、セットアップを再実行しても上書きしない。すでに変更済みの状態を「変更前」として再定義してはならない。

### 8.2 セットアップ順序

変更を伴わない検証とステージングを先に実施する。

1. 管理者権限、Windows環境、パス、引数を検証する。
2. ステージング領域でランチャーをコンパイルする。
3. 必要な場合はSunshineをステージング領域へダウンロードして検証する。
4. 同名の既存リソースを保存できるか、安全に拒否できるか確認する。
5. 変更前状態を取得し、永続化する。
6. システム設定とユーザー設定を変更する。
7. 検証済みのステージング成果物を所定位置へ移動する。
8. インストール完了状態を記録する。

PowerShellの高度な関数とSupportsShouldProcessを利用し、変更処理に-WhatIfを適用できるようにする。

変更開始後に処理が失敗した場合は、uninstallと共通の復元処理を呼び出し、その実行中に適用した変更だけを元に戻して非ゼロ終了する。

### 8.3 アンインストール

scripts/uninstall.ps1は記録済み状態を使用し、次を復元する。

- Child Sessionsの有効状態
- 変更したレジストリ値。元々存在しなかった値は削除する。
- Firewallルール
- スタートアップフック
- Scheduled Task
- デスクトップショートカット

ファイルやユーザーが作成したSunshineデータを回復不能な形で削除しない。稼働中の配置から取り除く必要がある場合は、%ProgramData%\ChildStream\Backups以下のタイムスタンプ付きディレクトリへ移動し、復元先を画面へ表示する。

状態ファイルが存在しない、または壊れている場合は、推測した値による破壊的な復元を行わず、手動復旧手順を表示する。

## 9. ログとエラー処理

ログへパスワード、DPAPIデータ、タスク資格情報、秘密情報を出力しない。

ランチャーはネイティブAPIの成否とWin32エラー番号を記録する。PowerShellスクリプトは、インストール段階、起動許可を拒否した理由、ハッシュ検証結果、ロールバック操作、バックアップ先を記録する。

セキュリティ上の曖昧さがある場合は、常に処理しない側へ倒す。

- 検証済みChild Sessionがない場合: 起動せず、ログオフもしない。
- display.cfgが不正な場合: RDP接続しない。
- ハッシュが一致しない場合: 展開しない。
- スナップショットが不完全な場合: システムを変更しない。
- 未知の既存リソースがある場合: 拒否するか、明示的な置換指定を要求する。

## 10. 自動検証

Windows版GitHub Actionsを、ソース・スクリプト・テスト・ワークフローの変更時に実行する。

次を検証する。

- セットアップと同じ.NET Frameworkのcsc.exeおよび参照アセンブリでランチャーをコンパイルする。
- display.cfgについて、既定値、正常形式、境界値、不正形式、オーバーフロー、範囲外を単体テストする。
- 起動許可について、一致、不一致、期限切れ、破損、PID再利用を想定した状態をテストする。
- すべてのPowerShellファイルを構文解析する。
- セットアップ計画、Firewall引数、ハッシュ強制、スナップショット維持、ロールバック、失敗時に何もしない挙動をPesterとモックでテストする。
- 固定バージョン、変更されないURL、SHA-256が空ではなく、相互に整合していることを確認する。

CIでは、実際のChild Session作成、複数同時セッションでのTask Scheduler配置、WGCキャプチャ、NVENC、Moonlightペアリング、管理者権限ゲームへの入力を検証済みとはみなさない。

## 11. Windows実機確認

Pull Requestには次の確認項目を記載する。

1. Windows 11 Proの未導入状態からセットアップできる。
2. -WhatIfでは変更が発生しない。
3. Child Sessionへ接続し、期待するSession IDが発行される。
4. 通常のRDPログオンではChildStream用Sunshineが起動しない。
5. コンソールへのログオンではChildStream用Sunshineが起動しない。
6. Child Session内だけでSunshineが起動する。
7. 最高権限モードでUACが表示されず、管理者権限のテストアプリケーションへ入力できる。
8. End sessionでAPIが返したChild Sessionだけがログオフされる。
9. 不正なdisplay.cfgでは、明確なメッセージを表示して接続しない。
10. FirewallルールがPrivateかつLocalSubnet限定である。
11. 改変したSunshineアーカイブが拒否される。
12. uninstallで記録済み設定が復元され、ユーザーデータが回復可能な場所へ退避される。
13. 2回目のセットアップで最初の変更前スナップショットが上書きされない。

## 12. 受け入れ条件

次をすべて満たした時点で、Fork内のPull Requestをレビュー可能とする。

- windows-latest上の全自動検証が成功する。
- ユーザー名によるセッション終了や、非コンソール判定によるChild Session推測がコードに残っていない。
- セットアップが利用するすべてのダウンロードが固定URLかつハッシュ検証済みである。
- setupとuninstallが、テスト済みの共通復元処理を使用する。
- READMEに固定Sunshineバージョン、Firewall範囲、UACなし起動の制約、フォールバックモード、状態ファイルの場所、回復手順を記載する。
- Pull Requestに残る実機確認項目を明記する。
